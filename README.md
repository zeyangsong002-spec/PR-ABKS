# PR-ABKS research implementation

Version 1.0.0, prepared 2026-10-13. MIT licensed; see [LICENSE](LICENSE).

C++17 implementations of PR-ABKS, PR-ABE and RR-ABKS, with correctness tests
and a benchmark that checks search/decryption results before exporting timings.
The benchmark uses synthetic inputs generated by the program; it does not need
an external dataset. Type-A pairing parameters are supplied in `params/a.param`.

This is the corrected implementation developed after the original experiments.
It supports new executions of the implemented algorithms. It is not an exact
reproduction package for the manuscript's historical numerical figures.
Read [the experiment mapping](docs/EXPERIMENT_MAPPING.md) before interpreting
benchmark results, and [implementation details](docs/IMPLEMENTATION.md) for
baseline conventions and scope.

## Install and run

Follow [INSTALL.md](INSTALL.md) on a fresh Ubuntu system or Windows with WSL
Ubuntu. Dependencies: C++17 compiler, CMake >= 3.18, PBC 0.5.14, GMP and
OpenSSL libcrypto. Python 3 is only needed for the optional sweep script.

After installing system packages listed there, run from this project's root:

```bash
bash scripts/install_pbc.sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$PWD/.deps/pbc-0.5.14"
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/prabks --self-test
./build/prabks --benchmark --output example_run.csv \
  --users 10 --attrs 10 --policy 4 --eta 3 --tags 1 \
  --punctures 1 --keywords 10 --runs 10 --warmup 1
```

Successful self-test prints `ALL 428 CHECKS PASSED`. Any failed check exits
nonzero. The output CSV path must not already exist. Timings are in milliseconds;
`total_ms` sums measured runs, `mean_ms` averages them, and `sample_sd_ms` uses
the sample standard deviation. `--` denotes unsupported/not-applicable fields
or an undefined standard deviation with one run. Warm-up runs are excluded.
Randomness and machine load mean timings are not bit-for-bit repeatable.

All three schemes run in one benchmark invocation. Pairing initialization is
outside the timers. KeyGen covers all users; Enc includes searchable indexes
where supported; Dec includes the complete recovery path. RR-ABKS validity
checking has a separate `IsValid` row. See the mapping for comparison details.

## Parameters

| Option | Meaning / constraint | Default |
|---|---|---|
| `--users` | Registered users N, at least 2 | 10 |
| `--attrs` | Attribute universe U, positive | 10 |
| `--policy` | Rows in the generated AND policy, 1 through U | 4 |
| `--eta` | Tag-polynomial coefficient-vector length, positive | 3 |
| `--tags` | Ciphertext tag count m, 0 through eta-1 | 1 |
| `--punctures` | Sequential distinct punctures, nonnegative | 1 |
| `--keywords` | Indexed and queried keyword counts (equal here), positive | 10 |
| `--runs` | Independent measured runs per scheme, positive | 10 |
| `--warmup` | Complete warm-up runs per scheme, nonnegative | 1 |
| `--params` | Explicit PBC parameter file | Project `params/a.param` |

The final user is excluded at index creation, so eligible users c=N-1. The
first two users have all attributes; subsequent users receive attribute w
when `(w + user) % 3 == 0`. User 0 queries and decrypts. Search benchmarks the
first matching identity, not the worst-case scan. Updates use tags different
from the target ciphertext's tags. The general LSSS interface is exercised by
AND, OR, mixed, threshold and non-integer reconstruction tests; the benchmark
CLI constructs AND policies only. PR-ABE uses the puncturable core, not the
outsourced Tra/OPR-ABE extension.

## Files and further use

- `src/main.cpp`: algorithms, self-tests and benchmark.
- `scripts/install_pbc.sh`: download, checksum and local PBC build.
- `scripts/run_sweep.py`: explicit parameter sweeps with command/configuration records.
- `docs/EXPERIMENT_MAPPING.md`: manuscript correspondence and unresolved historical settings.
- `docs/CLEAN_ENVIRONMENT.md`: independent userspace validation report.
- `THIRD_PARTY.md`: dependency provenance and licensing.
- `README_CN.md`: Chinese guide; `IMPLEMENTATION_NOTES.md`: detailed Chinese correction history.

The Type-A setting is retained for research comparisons and is not a production
security recommendation. Test success is not a cryptographic security proof.
The program does not implement attribute certification, operating-system secure
erasure, arbitrary keyword-subset queries or retroactive invalidation of old indexes.

If using this implementation in academic work, please cite the associated
manuscript, *Puncturable registered attribute-based keyword search for secure
cloud data sharing*, and identify this software version. A publication DOI and
repository URL have not been assigned in this local release. Citation is a
scholarly request, not an additional license restriction.
